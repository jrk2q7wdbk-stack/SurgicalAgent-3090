# 阶段5补充：正式微调前数值稳定性与长证据修复

## 1. 边界与结论

本次没有运行全量训练，没有使用或修改冻结测试集，没有修改RDV网络、权重或`rdv4`环境。所有新LoRA实验均从固定revision `7ae557604adf67be50417f59c2c2f167def9a775`的原始Qwen2.5-0.5B基础模型重新初始化，没有加载之前存在NaN告警的5步adapter。

两项修复均已通过预检：AMP初始scale固定为8192后，跨类型/跨长度稳定性短训练和小样本学习阶段均没有非有限梯度或跳过更新；模型证据与结构化事件输出采用共享列式schema后，2048 token下训练7,610条和验证1,100条全部保留。

## 2. FP16 `grad_norm=NaN`定位

诊断脚本：`tools/diagnose_fp16_lora.py`。每个对照都重新加载基础模型并新建LoRA。

实测参数精度：冻结基础参数494,032,768个，为FP16；可训练LoRA参数1,081,344个，为FP32。高初始scale运行中，LoRA参数始终有限，但缩放后的梯度溢出，`GradScaler`降低scale并跳过optimizer更新。跳步时192个LoRA张量中没有任何张量发生变化。

| 对照 | 学习率 | 初始scale | 结果 |
|---|---:|---:|---|
| 原配置复现 | 2e-4 | 65536 | 前3个诊断步梯度非有限、更新全部跳过，scale依次降至32768/16384/8192 |
| 仅降低学习率 | 5e-5 | 65536 | 与原配置相同，前3步仍全部溢出和跳过 |
| 仅降低初始scale | 2e-4 | 16384 | 第1步跳过，scale降到8192后第2、3步正常更新 |
| 稳定scale | 2e-4 | 8192 | 3/3步梯度有限，3/3步更新，192个LoRA张量均发生有限变化 |

溢出首先出现在连续事件、越界异常、缺视频等不同类型和不同长度样本上，不是单一坏样本。仅降低学习率不会改变反向传播前的loss scaling，因此不是该NaN的根因。根因是当前FP16路径默认初始loss scale对这些梯度过高；学习率仍影响后续收敛，但属于独立超参数。

历史Trainer运行记录的NaN步数与手工诊断步数因样本顺序和scaler状态不同而不同，但共同证据是：scale下降时更新被跳过，scale稳定在8192后梯度和参数更新恢复有限。

## 3. 工具证据与输出schema修复

完整注册工具结果仍写入日志和确定性评分。传给API、本地模型和训练对话的共享边界改为`surgical-agent-model-evidence/v2`：

- 器械、动作、靶点问题只保留对应实体、置信度、时间、状态和来源；
- 完整三元组和时刻操作保留全部器械—动作—靶点配对；
- 范围汇总保留全部去重三元组，不重复携带不用作该答案的事件明细；
- 连续事件使用三元组目录和列式事件区间，保留全部配对、开始/结束时间、左右截断标志以及被截断时的原始边界；
- RDV预测置信度仍可保留，人工真值中的重复实例、原始框、逐帧重复诊断和私有标注路径不进入模型上下文。

API、本地模型、现有Agent工具回填和训练导出均使用同一证据视图。最终事件答案协议升级为`surgical-agent-output/v2`，允许列式结构化事件；解析器在评分前恢复为原来的规范事件对象，因此现有事实匹配规则保持不变。

训练对话现在直接从标准化真值构建，使用与部署相同的系统提示，并监督助手工具调用和最终`STRUCTURED_JSON`。system/user/tool仍全部使用`-100`损失掩码。

## 5. 修复后稳定性短训练与小样本学习

入口：`tools/run_lora_preflight.py`。该程序从原始基础模型创建全新LoRA。

稳定性阶段选择八类任务各自的最短、中位和最长样本，共24条；最长训练样本1877 token。运行6个optimizer步骤、每步梯度累积4，学习率5e-5，初始scale8192。结果：无非有限梯度、无跳过更新、LoRA参数始终有限，未OOM。

随后在七类正常任务各1条的固定小样本上运行28步学习验证，独立验证使用不同视频/不同sample ID的七类样本：

| 指标 | 学习前 | 学习后 |
|---|---:|---:|
| 训练小样本平均loss | 0.9140 | 0.1593 |
| 独立验证平均loss | 0.9369 | 0.1938 |
| 训练小样本工具调用精确匹配 | 4/7 | 7/7 |
| 独立验证工具调用精确匹配 | 3/7 | 5/7 |

学习阶段28/28步梯度有限、28/28步未跳过更新。峰值实际分配显存4321.6 MiB，峰值allocator保留5422 MiB，总耗时138.8秒。新adapter保存在`artifacts/stage5/lora_preflight_fixed/adapter`。

重新加载该adapter后，通过统一评测器运行7条独立验证样本：工具选择5/7，正确工具条件下参数5/5，联合工具参数5/7。结构化答案自动覆盖仅2/7，完整任务成功0/7，全部仍进入人工复核，因此这不是正式性能结论，只说明工具选择已经出现可测学习。

## 6. 正式训练配置草案

配置：`config/local_lora_formal_draft.json`，仍标记为未授权执行。

- 基础模型：Qwen2.5-0.5B-Instruct固定revision；FP16 LoRA，r=8、alpha=16；
- 数据：训练7,610、验证1,100；序列上限2048；
- epoch：3；预计2,856个optimizer步骤；
- 每卡batch size 1，梯度累积8，有效batch size 8；
- 学习率5e-5，warmup 5%，初始AMP scale 8192，动态缩放；
- 每200步验证并保存，最多保留3个检查点；
- 主检查点指标：固定验证子集的工具与参数联合准确率；次指标为结构化答案自动覆盖率和eval loss；
- 测试集保持冻结，不参与提示词、阈值或检查点选择；
- RTX 2060 6GB预计约4～7小时，正式运行后应以首个200步区间重新估算。
